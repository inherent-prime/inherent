# Inherent — Terraform (Azure, cloud-native production)

Provisions the mission-critical Azure deployment: AKS in a VNet, PG Flexible Server, Cosmos
DB for MongoDB (vCore), Azure Cache for Redis, Blob storage, and Key Vault, then installs the
app stack via Helm. For the single-VM eval path see [`../`](../) (Hetzner); this root is the
production, HA+DR-capable path (issues #321/#322 and onward).

The full operator guide — architecture diagrams, prerequisites, TCO tables, enterprise
VNet integration, DR runbook — lives at
[docs/deploy/azure.md](../../docs/deploy/azure.md). This file is the quickstart.

## Prerequisites

- Azure subscription with quota for AKS, PG Flexible, Cosmos DB, Azure Cache for Redis,
  and Azure OpenAI access (embedding_profile = azure_openai, the default — see
  docs/deploy/azure.md prerequisites for the access-request lead time)
- `az`, `terraform` (>= 1.9), `kubectl`, `helm`, `jq`
- `az login` (or an OIDC-federated CI identity) with Contributor on the target subscription

## Setup

```bash
az login
cd infra/azure

cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars, or use envs/prod.tfvars.example / envs/dev.tfvars.example directly.
```

### Terraform init (pick one path)

| Path | When | State key / backend | Init |
|------|------|---------------------|------|
| **Prod / long-lived** | Stable prod cluster | `backend.hcl` stable key (e.g. `inherent/prod/terraform.tfstate`) | copy `backend.hcl.example` → `backend.hcl`, `az login`, `terraform init -backend-config=backend.hcl` |
| **Dev sandbox** | Small eval cluster | `backend.hcl` key e.g. `inherent/dev/terraform.tfstate` | same storage account, dedicated key; `terraform init -backend-config=backend.hcl -var-file=envs/dev.tfvars.example` |
| **CI** | `.github/workflows/azure-terraform.yml` | `fmt`/`validate` only — no real backend, `init -backend=false` | no state written |

- `.terraform.lock.hcl` is the **provider lock** — committed to git.
- `*.tfstate` is **state** — never commit; it contains every generated secret (see
  [Secrets](#secrets) below). Remote state uses an Azure Storage account with
  `use_azuread_auth = true` (RBAC, not a shared key) — see backend.hcl.example.
- **Hard rule:** never point a dev/test run at the production state key.
- Bootstrap the state storage account once (RG + storage account + container, private
  network access, RBAC'd) via `scripts/deploy-azure.sh --bootstrap-state` or manually in the
  Azure console/CLI — out of band, same as Hetzner's Object Storage bucket. The bootstrap
  path grants the deploying identity **Storage Blob Data Contributor** scoped to that one
  container — the RBAC role `use_azuread_auth = true` actually needs at `terraform init`
  time, not just Contributor on the resource itself.

#### Remote state (production)

```bash
cp backend.hcl.example backend.hcl
# Edit backend.hcl: resource_group_name, storage_account_name, container_name, key

terraform init -backend-config=backend.hcl
```

## Deploy

**Two-phase apply — required on a fresh cluster.** `providers.tf`'s `helm`/`kubernetes`
provider blocks are configured from `module.aks`'s outputs (cluster host, client cert/key).
On a brand-new cluster those outputs don't exist yet when Terraform first evaluates the
provider config, so a single `terraform apply` fails trying to plan `module.apps`'s
`helm_release`/`kubernetes_*` resources against a cluster that isn't there. Apply `module.aks`
(and its dependencies) first, then run the full apply — both steps are idempotent, so this is
safe to re-run on every deploy, not just the first one:

```bash
terraform apply -target=module.aks -var-file=envs/prod.tfvars.example
terraform apply                     -var-file=envs/prod.tfvars.example
```

`scripts/deploy-azure.sh` automates exactly this two-step sequence on every run — see
docs/deploy/azure.md "One-click deploy" for the full walkthrough:

```bash
scripts/deploy-azure.sh --bootstrap-state --yes -- -var-file=envs/prod.tfvars.example
```
(preflight → backend bootstrap → `apply -target=module.aks` → full `apply` → wait for
`/health/ready` → optional load test).

## Secrets

Every credential (PG/Cosmos/Redis passwords, Weaviate/ingestion API keys, MinIO root
credentials) is generated by Terraform (`random_password`/Azure-issued) and written to Key
Vault — **no secret is ever a tfvar**.
Workloads read them at runtime via the CSI Secrets Store driver, using the workload identity
`modules/security` creates and grants `Key Vault Secrets User`.

That still means every one of those values **lands in Terraform state**: `sensitive = true`
on an output only redacts it from CLI plan/apply text — the raw value is still readable by
anyone with state access. The backend storage account (see [Terraform
init](#terraform-init-pick-one-path) above) MUST have public network access disabled and use
RBAC scoped to the one container — treat it as security-critical infrastructure, the same
discipline [docs/getting-started/deploy-hetzner.md](../../docs/getting-started/deploy-hetzner.md#setting-application-secrets)
documents for the Hetzner root's state.

## Clean up

```bash
terraform destroy -var-file=envs/prod.tfvars.example
```

Key Vault has purge protection enabled — a destroyed vault soft-deletes and is recoverable
for `soft_delete_retention_days` (90), not immediately purgeable.

## File layout

```
infra/azure/
├── versions.tf              # Terraform & provider versions; partial azurerm backend block lives in backend.tf
├── backend.tf                # Empty backend "azurerm" {} — see backend.hcl.example
├── backend.hcl.example        # Azure Storage backend config template
├── providers.tf               # azurerm features{}; helm/kubernetes wired from modules/aks outputs
├── main.tf                    # Module composition only
├── variables.tf                # All root input variables
├── outputs.tf                  # api_fqdn, aks_name, kv_uri, pg_fqdn, kubeconfig command, ...
├── terraform.tfvars.example    # Documented example, every knob at its default
├── envs/
│   ├── prod.tfvars.example     # HA+DR on, pinned inherent_version
│   └── dev.tfvars.example      # HA/DR off, small SKUs
├── modules/
│   ├── network/                 # VNet, subnets, NSGs, private DNS zones, NAT gateway (#321)
│   ├── security/                # Key Vault, workload identity, generated secrets (#321)
│   ├── data/                    # PG Flexible, Cosmos Mongo vCore, Redis, Storage (#322)
│   ├── aks/                     # AKS cluster
│   ├── ai/                      # Azure OpenAI embedding deployment
│   ├── apps/                    # Helm releases: public-api, ingestion, weaviate, minio, temporal
│   ├── monitoring/               # Log Analytics, Container Insights, alerts
│   └── dr/                       # Secondary-region storage, optional PG geo-replica, runbook outputs
├── .terraform.lock.hcl          # Provider dependency lock (committed)
└── README.md                     # This file
```

State/`backend.hcl`/`*.tfvars` are already ignored by [`../.gitignore`](../.gitignore) —
its patterns apply to this subdirectory too, no separate `infra/azure/.gitignore` needed.
